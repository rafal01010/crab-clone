# Source catalogue

This directory contains internal research for the pinned Everything is Crab 1.2.1 baseline. Source names identify mechanics for comparison. They are not product names or permission to reuse source assets.

`source-catalogue.json` replaces the old CSV as the working reconciliation record. It retains every seed candidate's disposition, canonical candidate ID, evidence, proposed hovercraft translation, and unresolved questions. `coverage.tsv` maps abilities and specialization options to implementation owners. Neither file is a production gameplay registry. Every record remains research-only until its required fields are resolved and its behavior is verified.

`node scripts/generate-research-graph.mjs` refreshes the blocked graph entries used for hypothetical build-path search. Unresolved prerequisites are treated as open and unresolved specialization triggers as rank three or the parent's maximum rank, whichever is lower. These assumptions do not make a card selectable or establish source fidelity. Implemented definitions override the generated entries.

## Field meanings

- `candidateFields` holds reported research values. It does not establish version fidelity. Partial numerical examples retain their older-reference label.
- `availability.prerequisites` represents all-of, any-of, minimum rank, and specialization conditions. `unresolved` differs from an explicit `none` condition.
- `availability.exclusions` contains normalized symmetric candidate bans. Conditional rank caps remain in `rankConstraints`; converting those caps to whole-ability bans would lose acquisition-order behavior.
- `bundleRelationships` preserves the seed's original prerequisite, exclusion, and reverse-unlock text so a correction cannot erase its source.
- `questions` names the source fields still requiring confirmation. Each question has an owner. A missing table or empty candidate field is not a zero effect or evidence of no prerequisite.
- `specializations` has a separate identity for each known option. Names do not justify invented effects. The parent owns each option's trigger, permanence, skip transaction, and numerical behavior.
- `releaseState` prevents research status from being mistaken for approval. A production content release must reject required unresolved fields rather than fill them with generic bonuses.

## Inventory reconciliation

The seed combines an older 103-ID inventory, six additions reported in developer patch notes, and three wiki candidates. These are different inventories, not an arithmetic proof of a current playable total. The record preserves 112 seed dispositions. Its 112 canonical candidates include a separate Bop and a provisional Carrion-to-Scavenger mapping. The equal counts are incidental.

The [older inventory](https://hinamizawa.ai/everything-is-crab/evolutions/) labels the hidden starting attack as Body Slam while its detail names Bop. Learned Body Slam scales with maximum HP. The two remain distinct. The tail-labelled variant is provisionally mapped to learned Body Slam, rather than offered as a duplicate; its versioned identity remains a checkpoint question documented in the source catalogue.

The [Neoseeker reference](https://www.neoseeker.com/everything-is-crab/Evolution_Traits) reports Turtle Down with Hide-prefixed fields. The current canonical candidate is Turtle Down, with timed protection and contact-block stun. The legacy stealth description is rejected. Its alias mapping still needs versioned confirmation before release. Basic Dash is another hidden starting action rather than a normal offer.

Subcutaneous Fat is a candidate missing under that name from the CSV. The Fat mapping remains provisional. Carrion and Scavenger also need versioned ID comparison. The [trait index](https://www.neoseeker.com/everything-is-crab/Evolution_Traits) lists Resistant as ID 1021 and Hyperkeratosis as ID 1204, each with zero upgrades and a placeholder description. The community evolution inventory describes neither as a selectable evolution. The inspected local build now resolves these internal names through localization to Immune System and Fibroblasts. The canonical imports use those identities. Their older separate candidates remain assigned to graph reconciliation, and 1.2.1 parity is unverified.

The [Spit card](https://everythingiscrab.wiki.gg/wiki/Spit) supports the previously missing Beak-rank-two, Jaws, or Saliva prerequisite. The [1.1 notes](https://steamdb.info/patchnotes/23879270/) and local crosswalk identify Tracker, Lick Wounds, and later specialization and rarity changes. The indexed cards for [Slow Metabolism](https://everythingiscrab.wiki.gg/wiki/Slow_Metabolism), [Saliva](https://everythingiscrab.wiki.gg/wiki/Saliva), [Forager](https://everythingiscrab.wiki.gg/wiki/Forager), [Cheek Pouch](https://everythingiscrab.wiki.gg/wiki/Cheek_Pouch), [Reach](https://everythingiscrab.wiki.gg/wiki/Reach), [Ruminant](https://everythingiscrab.wiki.gg/wiki/Ruminant), [Herbivore](https://everythingiscrab.wiki.gg/wiki/Herbivore), [Carnivore](https://everythingiscrab.wiki.gg/wiki/Carnivore), and [Piscivore](https://everythingiscrab.wiki.gg/wiki/Piscivore) supplied rank tables and effects on 2026-11-16. The Match retains one roll per resource and evaluates it against each claimant's Forager bonus when first consumed, because shared drops have no single owning build. Cheek Pouch reserves nearby whole resources and consumes them in acquisition order. Provider uses a five-unit radius, attempts a 20% charm on each eligible nearby wild bot, and heals nearby owned charmed bots by Gregarious affinity. Ruminant grants its listed amount every ten seconds and resets that timer after damage. The source does not establish how the timer behaves across a hit, so the reset is an estimate.

Run `node scripts/audit-catalogue.mjs` to check catalogue identities, ownership, evidence references, field-level evidence or owned questions, prerequisite targets, specialization targets, and symmetric exclusions. Its reachability calculation treats unresolved prerequisites as potentially satisfiable and ignores acquisition-order restrictions and exclusions. It detects some broken references and cycles but does not prove a legal build or establish source accuracy.

The host also registers the project's fixed Standard starting configuration. The agreed rule gives each player a +15 maximum-health bonus; it is not a selectable evolution. The Match records the bonus once per player. Health totals, damage, and healing are implemented by the later health work, so this is not evidence of complete combat behavior. The source upgrade records remain research-only.

Run `python3 scripts/audit-inventory.py` to compare the seed rows with the research catalogue and inspect reverse unlocks. ## Configuration imports and remaining ownership

[The retained configuration](local-game-configuration.json) contains all 1,687 decoded records from the inspected build, including numerical tables, curves, enum values, constraints, evolution metadata, and asset references. Every record has implementation owners and a disposition. `appliedFields` identifies current consumers. All other gameplay fields remain required work for those owners. Reference-only and outside-scope records are retained without making them playable. Boss content remains excluded.

`source-catalogue.json` now links matching abilities to those actual local records through `localConfiguration` and `candidateFields.numericalTables`. Their source questions remain open where formulas, version parity, or behavior need verification. This replaces missing-table placeholders with usable data; it does not approve unfinished mechanics.

`python3 scripts/extract-gameplay-tuning.py` regenerates the selected world settings. `python3 scripts/reconcile-game-data.py` regenerates the complete retained configuration, catalogue links, and `server/content/source-balance.ts`. Both read the ignored local `objects.json`; the application consumes generated TypeScript and needs no original game files. The Unity extractor includes basic and HP food components so the healing values can be reproduced from a fresh extraction. Run Prettier on the generated files after regeneration.

Current consumers use source tables for 62 upgrades, 40 player base stats and limits, Bop and Dash, 66 regular/alpha enemy profiles, enemy food quantity and rarity weights, currency-drop weights, the XP requirement curve, healing-food chances and bite amounts, Robust's size coefficient, and Shifty's coefficients. The existing population, offer-rarity, charm, Tail Wag, burrow, and mushroom timing imports remain active. Damage ranges are rolled for implemented attacks; cards show ranges. Poison ticks currently use the source range midpoint. Branching upgrades use the source boss/branching rarity channel rather than zero-filled ordinary channels. Single-row settings repeat at higher ranks.

These imports supersede earlier estimated tables where a consumer exists. They do not settle the original runtime formulas. The implementation uses the XP curve at `level - 1`, interprets the final HP-food flat amount as replacing the normal flat amount, rolls uniformly within damage ranges, and treats each generic enemy contact hit as one base-physical-damage unit. The original executable formulas have not been recovered. The current multiplayer species selection and stage schedule remain adaptations. Late-alpha HatBirb temporarily reuses its mid-alpha loot table because this extraction has no named late-alpha loot record. Stoner's reload timing and physical/ability combination remain reconstructed. Starting bonuses, per-level hull growth, food-contribution stacking, and secondary specialization formulas still require reconciliation.
